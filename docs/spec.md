# 仕様書

アプリの「何を・どう動かすか」を書く。AIは作業の前に必ずここを読む。

## 目的

飲み会の割り勘を、先輩・後輩の傾斜つきで1分で決めて、LINEにそのまま貼れる文面にしてくれるWebアプリ。（元のメモ：飲み会の割り勘を、先輩・後輩の傾斜つきで1分で決めて、LINEに貼れる文面にするWebアプリ）

## 前提

- 使う人・使う場面（デザイン担当の分析。推定を含む）：
  - 使う人：飲み会の幹事をする若手の会社員・大学のサークルの幹事。上司・先輩・後輩が混ざった会で、誰がいくら払うかを決めて集金する人
  - 使う場面：店を出る前や帰りの電車で、会計の伝票を見ながらスマホ片手に1分で決め、LINEのグループにそのまま貼る（開くのは会計のときの1回）
  - 受け取る人：文面のURLを開いた参加者が、自分の区分を押して金額だけを確かめる
- 技術：Next.js（App Router）＋TypeScript、テストはVitest

## 画面

（ページごとに、何を出して何ができるか）

### 飲まない人の計算（`src/lib/split.ts`）

- 入力：区分ごとの「うち飲まない人」の人数 `abstainers`（`counts` と同じ順・長さ。0〜その区分の人数。超えたらその人数に直す）と、割引率 `discount`（全体で1つ。0〜0.5、0.1 刻み、初期値 0.3）
- 重み：飲まない人の重み＝同じ区分の重み×(1−割引率)。合計は変えず、重みに比例して全員の金額を決める（その結果、飲む人の金額が上がる）
- 端数：切り上げ・上の区分が持つ、どちらも今までと同じ考え方を、区分の「飲む人」と「飲まない人」それぞれに適用する。上の区分が持つときの足りない分は、いちばん上の区分の飲む人が持つ（その区分が全員飲まない人なら、飲まない人が持つ）
- 結果：`TierShare` に `abstainers`（人数）・`eachAbstain`（飲まない人の1人分）・`subtotalAbstain`（小計）を足す。`each` は飲む人の1人分、`subtotal` は区分の合計（飲まない人を含む）。飲まない人がいない区分は `eachAbstain` ＝ `each`。`abstainers` が全部 0 のときは今までの結果と同じ
- LINE の文面：飲まない人がいる区分の行に「後輩　2,400円 ×2人（うち飲まない1人 1,800円）」のように足す。区分の全員が飲まないときは、飲まない人の金額を出して「（全員飲まない）」（1人なら「（飲まない）」）。飲まない人がいなければ今までと同じ
- 画面：「区分と人数」の各行（人数が1人以上）に「うち飲まない人」の増減（0〜その区分の人数。人数を減らして超えたら飲まない人も減らす）。飲まない人が1人以上いるときだけ、その下に割引率の増減（10%刻み）を出す。文言「飲まない人は 30% 引き」
- URL の query：`a`（区分ごとの飲まない人、`c` と同じ「-」区切り）と `d`（割引率の%の整数）。飲まない人が全員 0 のときは付けない。無い・読めない・範囲外のときは、飲まない人 0・割引率 30% に、範囲内へ直して読む
- 内訳のページ（`/r`）：表と金額は飲まない人を含めた結果。飲まない人がいる区分の1人分に「（飲まない1人 1,800円）」を添える
- 内訳のページ（`/r`）の欠けたとき（合計金額が 0、または人数が 0 で `ready` でないとき）：坂の枠は空の坂（床の線だけ）になり、案内文「この内訳には、金額か人数が入っていません」を坂の枠の幅いっぱいに横書きで出す（中央寄せ）。区分ごとの表（「0円」「0人」の行）と「幹事まで、お願いします。」は出さない。見出し「区分ごとの金額」と「計算の画面で入れ直してください。」と「この内容で計算し直す」は出す。金額と人数が揃った内訳は、上の表示のまま

### 区分の名前（`src/lib/split.ts`）

- 区分は5つのまま（足す・減らすはしない）。名前は上から順に5つ `names`（`SplitInput`／`SavedState`）。初期値は 上司・先輩・同期・後輩・新人。無い（未指定）ときは初期値
- 直し方（`sanitizeNames`／`sanitizeName`、画面・URL・保存で共通）：制御文字と前後の空白を削る、見た目で8字（`Array.from` の長さ）まで、空になったらその区分の初期値、配列が足りなければ初期値で埋める。同じ名前が2つあってもよい
- `computeSplit` の `tier`、`roundingNote`・`roundingHead`・`buildLineText` は変えた名前を使う。画面の計算・傾斜の文・席順の坂・表・「〇〇のあなた」も同じ。区分の色は位置で決まり、名前では変わらない
- 画面：「区分と人数」の札が入力欄。入力は8字で切り、空のまま外に出ると初期値に戻る
- URL の query：`g`（5つの名前を改行で区切る）。すべて初期値のときは付けない（今までのURLと同じ）。読めない所は初期値

### 前回の会計の記憶（`/`）

- 覚える物：会の名前・合計金額・区分ごとの人数・倍率・単位・端数の持ち方・幹事の名前・区分ごとの飲まない人・割引率・区分の名前。古い保存（飲まない人・割引率の項目なし）は、飲まない人 0・割引率 30% として、名前の項目なしは初期値として読む。直近の1件だけ。端末の `localStorage`（1つのキー）に JSON で残し、どこにも送らない
- 保存：値が変わるたびに自動で保存する（保存ボタンは無い）
- 戻す条件：URL に会計の query（`t`）が無い `/` を開いたときだけ、マウント後に保存した値で画面（合計金額の入力欄の表示も）を戻す。保存が無い端末では、既定の会計（部署の忘年会 48,600円）のまま
- URL に会計の query があるとき（`/?t=...`、文面の URL）と `/r?...` では、保存した値で上書きしない。開いた値で保存も上書きしない
- 読み込みの直し方：壊れた JSON・オブジェクトでない物は捨てる（何も戻さない）。項目ごとに、型が違えば既定の値、範囲外なら範囲内に直す（人数 0〜99、倍率は 1.0〜3.0、単位は 10/100/500/1000 のどれか、会の名前 30字、幹事の名前 20字）
- `localStorage` が使えない（例外）ときも、画面は壊さず、そのまま動く
